## 4. Qué validar y con quién

**Con un responsable del proceso agrícola:** validar D1–D7 como reglas operativas. Llevar un ticket real o descripción de su numeración para D1; modalidad y resolución de balanza/evidencia para D2; combinaciones permitidas y reparto para D3/D5; tratamiento y autorización de diferencias/merma para D4; punto exacto donde calidad habilita consolidación y determinación de H para D6; responsables, centros, segregación de funciones y corrección para D7. No sustituir esta validación por una relación muchos-a-muchos en el modelo conceptual.

**Con la docente:** confirmar frontera del siguiente incremento y suficiencia académica de las simplificaciones de D1/D2/D3/D5; si calidad puede quedar fuera según D6; y si permisos, revisión de discrepancias y correcciones diferidas de D4/D7 cubren lo exigido. Presentar C4 implementado frente a objetivo y ratificar el avance al Sprint 2. Las observaciones académicas pueden exigir ampliar el corte; no fijan por sí solas pesos, tolerancias o compatibilidad física del producto salvo validación explícita del proceso.

**Con el usuario/equipo:** registrar por cada D la opción elegida, excepciones, quién la validó, fecha y ejemplo aceptado. Si la docente admite una simplificación solo para demostración, dejarla marcada como tal, sin presentarla como regla real. No contactar a terceros ni fusionar PR hasta recibir instrucciones. No implementar funciones dependientes mientras falten las respuestas.

Dependencias para retomar: D1/D2 condicionan recepción y medición; D4/D7 condicionan confirmación y excepciones; D3/D5/D6 condicionan elegibilidad, aportes y saldos; D7 afecta todas las escrituras. La tabla completa debe responderse antes de cerrar contrato API, transiciones y esquema físico. No crear ahora rutas, roles ni migraciones a partir de estas recomendaciones.
